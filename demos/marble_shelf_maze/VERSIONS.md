# marble_shelf_maze demo versions

Each file is a side-by-side video: left = `head_camera` (current/overhead view), right = `front_camera` (robot's front view).

- **v1** (`marble_shelf_maze_v1_demo.mp4`): baseline settings -- shelves raised ~10cm, shelf thickness (z) halved to 0.00625m, both glass sheets transparent (open-frame), correct tilt direction with turn-arrow decals on the buttons. `natural_ball_stop` and `smooth_tilt` both off (default): marble snaps to shelf center on landing, shelf tilts snap to 45deg over a fixed 0.5s.
- **v2** (`marble_shelf_maze_v2_demo.mp4`): same geometry as v1, but with `natural_ball_stop: true` and `smooth_tilt: true` enabled -- the marble settles wherever real friction/gravity leave it after landing (no re-centering snap), and each button press produces a slow, visibly gradual 0->45deg tilt (30 deg/s) instead of an instant sweep.
- **v3** (`marble_shelf_maze_v3_demo.mp4`): 3-episode montage with `n_shelves_min: 3` / `n_shelves_max: 6` -- the number of shelves (and thus the length + left/right pattern of the required button-press combination) is drawn randomly per episode instead of being fixed at 4. Episode 0 = 3 shelves, episode 1 = 4 shelves, episode 2 = 6 shelves in this recording; the bowl always sits under whichever shelf ends up on the bottom, so a deeper stack needs a longer combo and a shallower one needs a shorter one. `n_shelves` (2-6) also works as a plain fixed value if randomization isn't wanted.

- **v4** (`marble_shelf_maze_v4_demo.mp4`, single `head_camera` view -- not a side-by-side montage): the whole shelf stack is now re-centered on the table's x=0 midline every episode (previously the zig-zag could drift off-centre depending on the random offsets drawn). The vertical gap between each pair of consecutive shelves is now randomized independently per level (`level_gap_jitter`, default +/-35%, renormalized so the total stack height -- and so the camera framing -- stays the same). The horizontal overlap between consecutive shelves is now driven by `overlap_min`/`overlap_max` (default 30%-75% of shelf_length, randomized independently per level) rather than a fixed offset range. Fixing reliable success with these wider/more-varied per-level offsets also surfaced and fixed two pre-existing scripted-policy bugs: (1) a shelf landing was only checked once, after a fixed dwell -- now checked every simulation step (with a small velocity gate to avoid false positives from a marble merely transiting past a lower shelf's overlapping span while still mid-fall) so the marble is caught the instant it actually lands rather than after it's had time to roll past a narrow shelf's edge; (2) the expert policy indexed the next press's direction by a loop counter instead of the marble's actual current shelf, which pressed the wrong button if a fall ever skipped a level. With both fixes, empirical success rate across 40 random seeds (4-shelf, default overlap/jitter ranges) is ~93%.

- **v5** (`marble_shelf_maze_v5_demo.mp4`, single `head_camera` view, labeled 3-clip montage): shows the depth/geometry variation together -- `n_shelves_min: 4` / `n_shelves_max: 6` with the new per-level `overlap_min`/`overlap_max` (30%-75%) and `level_gap_jitter` (default) both active. Clips are `4 shelves` / `5 shelves` / `6 shelves` (labeled on-screen top-left), each a genuinely different randomly-drawn episode -- so besides the shelf count, every clip also shows a different zig-zag overlap and a different set of per-level vertical gaps, all still re-centered on the table's x=0 midline and framed the same regardless of depth.

- **v6** (`marble_shelf_maze_v6_demo.mp4`): same 4–6 shelf / randomized gap+overlap setup as v5, but with the updated button arrows -- open C-shaped turn arrows that are exact left-right mirrors of each other (blue = mirror of red) instead of the near-full circles that looked identical from the demo camera. Montage: two different 5-shelf zig-zags, then a 6-shelf episode.
